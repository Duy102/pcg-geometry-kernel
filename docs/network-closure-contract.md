# Network Closure Contract — Phase 5A

## Source theorem

This module is grounded in `PCG_Network_Closure_Theorem_v0.1.tex`.

Source SHA-256:

`6d1f8fc39b3bb34385956c4d2c0e77e222260f60d2f59fde860d6c1964aa8546`

The source theorem states that for a connected directed quotient multigraph of a cyclic PCG trace with fixed non-full turns, a metric endpoint skeleton exists exactly when the cycle-space Network Closure matrix has a strictly positive kernel vector:

```text
exists c > 0 such that N(G,alpha) c = 0.
```

The source also defines projective rigidity by `dim ker N = 1` and states the Stiemke dual alternative for failure of positive closure.

## Phase 5A software domain

The production kernel currently represents every turn as an exact rational multiple of pi. Therefore every induced chord phase is also a rational multiple of pi.

For a common chord-phase denominator L, Phase 5A works in the cyclotomic field generated by a primitive root of unity of order `4L`. This allows both sine and cosine direction entries to be represented by exact algebraic elements rather than decimal approximations.

To keep exact field arithmetic bounded in this first implementation, `4L <= 256` is required. Larger orders return `INDETERMINATE / CyclotomicOrderLimit`. This is a software-domain limit, not a theorem restriction.

## Exact topology and algebra

The module constructs a fundamental cycle basis of the quotient multigraph. For each basis cycle it builds the two Cartesian Network Closure rows using exact cyclotomic representations of cosine and sine.

Gaussian elimination is performed inside the cyclotomic number field. Consequently:

- zero tests for matrix entries are exact;
- matrix rank is exact;
- kernel dimension is exact;
- a one-dimensional kernel generator is algebraically exact;
- full column rank is an exact obstruction to closure.

## Sign certification

Projectively rigid closure additionally requires the exact one-dimensional kernel generator to have one strict sign after a global rescaling.

The algebraic values themselves are exact. Their real signs are currently separated with the existing directed-rounding interval TCB. Therefore:

- `ExactFullRankObstruction` has `ArithmeticAssurance::Exact`;
- `CertifiedPositiveRigidKernel` has `ArithmeticAssurance::CertifiedNumerical`;
- `CertifiedRigidSignObstruction` has `ArithmeticAssurance::CertifiedNumerical`;
- if the interval TCB cannot separate a nonzero algebraic sign from zero, the result is `INDETERMINATE / SignCertificationLimit`.

No guessed epsilon is used to decide a sign.

## Higher-dimensional positive kernels

The source theorem solves metric closure in general by positive linear feasibility even when `dim ker N > 1`.

Phase 5A deliberately stops before that general positivity solver. If exact rank computation gives kernel dimension greater than one, the implementation returns `INDETERMINATE / HigherDimensionalKernel`.

This is the principal remaining Network Closure item for Phase 5B.

## Certificates

For a projectively rigid supported instance, the certificate stores the exact cyclotomic-order identifier, exact matrix rank, and the exact algebraic kernel generator in the power basis of `Q(zeta_n)`.

The verifier rebuilds the theorem matrix, checks the stored rank, verifies `N c = 0` algebraically, verifies reality by exact cyclotomic conjugation, and then certifies the required signs.

For full column rank, the verifier recomputes exact rank and requires the kernel certificate to be empty.

## Scientific boundary

`CLOSED` in this module means metric endpoint skeleton closure only. It is not a top-level PCG realizability decision. It does not certify prescribed vertex non-collision or absence of unintended finite-arc intersections.

The source theorem explicitly places those checks after metric closure; the production architecture keeps the same separation.
